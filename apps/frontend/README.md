# Дашборд транспортной сети

Рабочий интерфейс для текущего локального backend: карта и выбор ТС, поиск, фильтрация свежести, карточка, история прогнозов и CSV, диагностика. Макет адаптирован через Stitch MCP из Transit Network Analytics Dashboard, экран `32160f4d02334680949b1c69d972dfcf`, дизайн-система Glacier Light Transit.

## Запуск

Из корня проекта:

```sh
scripts/dev/run-backend.sh
```

Откройте http://127.0.0.1:8000/ и введите значение `TRANSPORT_API_TOKEN` из своего `.env`. Токен не встраивается в HTML, не записывается в localStorage/sessionStorage и не отправляется в URL. После перезагрузки вкладки нужен повторный вход. Для удалённого доступа требуется HTTPS на reverse proxy.

Интерфейс на нативных ES-модулях и CSS, без сборки и внешних JS-зависимостей. Это сознательно небольшой клиент для существующего FastAPI: React/Vite из целевой архитектуры не требуются для запуска этого среза. Docker также копирует исходники интерфейса. API и UI находятся на одном origin.

## Данные и ограничения

- `/dashboard?limit=200` даёт согласованный снимок, общий счётчик транспорта и курсор SSE. В списке и карте максимум 200 ТС, ограничение подписано. Поиск/фильтры действуют в этой выборке.
- `/events?after=...` читается через fetch с Authorization; переподключение использует последний курсор. `resync_required` вызывает новый снимок. Контрольный опрос каждые 15 секунд и объединение событий в обновления раз в 350 мс.
- `/vehicles/{id}` даёт карточку и последние прогнозы; `/predictions` и `/data-issues` — последние 200 результатов. Счётчик прогнозов считает уникальные ТС с успешным последним результатом в этой выборке, не весь парк.
- Свежесть — возраст `event_time` до 120 секунд (UI-индикатор, не правило риска бэкенда). Время показано в Europe/Moscow. Карта использует последнюю пригодную позицию и отдельно предупреждает о невалидном GPS последнего пакета.
- Карта: географическая проекция Web Mercator, перемещение мышью/касанием/стрелками, масштаб кнопками. Подложка OpenStreetMap требует интернета. Без неё остаются маркеры по координатам и сообщение об отсутствии подложки; сетка не выдаётся за географическую карту.
- `delay_s=null`, ошибка ML и отсутствие результата показаны как недоступность, а не нулевое отставание. Инциденты, диспетчерские команды, пассажиропоток и вычисление маршрутов не реализованы бэкендом и не имитируются.
- Данные при ошибке обновления остаются на экране с предупреждением. Выход очищает UI, токен и останавливает SSE.

## Проверки

```sh
.venv/bin/python -m pytest -q
node --test apps/frontend/tests/*.test.js
```

Браузерный тест требует Playwright с Chromium и **отдельного тестового** backend: он создаёт устройства и телеметрию. Не используйте рабочую БД.

```sh
TEST_BASE_URL=http://127.0.0.1:8765 TEST_API_TOKEN=your-test-token node apps/frontend/tests/browser.cjs
```

Для снимков задайте `SCREENSHOT_DIR`. Playwright нужен только для тестов, не для интерфейса. Проверяются неверный/верный токен, снимок, выбор, поиск, свежесть, настоящее обновление API → worker → SSE → браузер, вкладки, CSV, отсутствие сети и восстановление, мобильная ширина и выход.
