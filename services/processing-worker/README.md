# services/processing-worker

Обработка телеметрии, состояния ТС, расписания, прогнозов и жизненного цикла ситуаций в одном процессе.

Статус на 27.09.2026: реализован локальный end-to-end профиль с внешним `ml-service`. Запуск и ограничения — `docs/development/backend.md` от корня репозитория. Ниже сохранены границы целевой полной системы; не все её возможности входят в локальную поставку.

## Входы, выходы и зависимости

В текущем локальном профиле worker читает долговременно сохраненную телеметрию и расписание, собирает immutable `PredictionBatch` с полной плановой `schedule_context`, вызывает внешний ML API и сохраняет `PredictionResult`. В целевой схеме источником потока остается Kafka.

## Границы ответственности

Общие правила ситуаций находятся в packages/domain. Worker не выполняет модельную предобработку и не заменяет пользовательские действия backend.
